dzcontent."tblBasePath" は「設定されたコンテンツディレクトリ」ではない。 CMS が登録済みコンテンツを持つベースパスの記録であって、両者は包含関係にすらない。実測(2026-08-27):

Poser Formats は Content Directory Manager の別リストで、CMS に行を持たないことが多い。したがって Poser ライブラリ配下は原理的にインデックスへ到達できなかった。

正しい情報源は動作中の DAZ Studio(App.getContentMgr())で、Script Server 経由で引ける。get-content-dirs スクリプトは元から存在したが、2 つの欠陥で常に空を返していた。

  • mgr.getContentDirectory(i) はパス文字列ではなく DzContentFolder オブジェクトを返す。正しくは getContentDirectoryPath(i)。加えて native リストしか見ていなかった
  • get_content_directories() はレスポンス最上位の paths を読んでいたが、プラグインはスクリプトの戻り値を result で包む

どちらも例外にならず [] が返るだけなので、誰も気付いていなかった。両方を直し、3 リスト(native / poser / other)を対象にしたうえで、resolve_content_roots() で CMS のベースパスと和集合を取る。古い CMS 行は無駄な走査 1 回で済むが、ルートの欠落はコンテンツを永久に不可視にするため。DAZ Studio 停止中は従来どおり CMS 側だけにフォールバックする。
